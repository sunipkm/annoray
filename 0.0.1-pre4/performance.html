Performance#

annoray is compared against xarray configured for speed: xarray with bottleneck, flox, numbagg and dask installed, as a performance-minded user would have it. The script is annoray-python/bench/bench_large.py. It checks every annoray result against xarray’s before timing it.

Setup#

Machine

AMD Ryzen 7 9700X (8 cores, 16 threads), 60 GB RAM, Linux 7.0

Software

Python 3.14.4, NumPy 2.5.4, xarray 2026.9.0, bottleneck 1.6.0, flox 0.11.2, numbagg 0.9.6, dask 2026.8.0, netCDF4 1.7.4, h5netcdf 1.8.1, zarr 3.4.1

Data

A year of hourly 2 m temperature on a 1° grid: time 8760 × lat 181 × lon 360, float32, 2.3 GB of values

Files

netCDF-4 uncompressed (2.28 GB; chunks 24 × 181 × 360), netCDF-4 zlib (1.28 GB), Zarr v3 zstd (1.83 GB; same chunks)

How the numbers were measured:

  • Times are medians of 3 runs, after a warm-up run, with the page cache warm.

  • Peak memory is the process’s peak anonymous memory while the timed runs execute, sampled from /proc/self/status. It counts allocations only, not the pages of memory-mapped files, which the operating system can reclaim.

  • Isolation: each file case runs in a fresh process, and one result is alive at a time.

python bench_large.py --generate             # write the files once (~5.4 GB)
python bench_large.py --repeat 3 --json out.json
python bench_large.py --only io              # or: --only compute

  • Reading.

    • annoray loads with one copy of the data. Chunks are decoded in parallel straight into the result.

    • Streamed reductions keep a few slabs in memory.

  • Writing.

    • Values that encoding leaves unchanged are borrowed from the dataset, not copied.

    • The netCDF-4 write is bound by the disk on this machine.

  • Zarr. annoray’s Zstandard is pure Rust (ruzstd). Its decoder is about 2× slower than libzstd’s and its encoder about 4× slower, with about 20 % larger output. Zarr reads and writes with zstd are bound by it.

  • Rolling means. xarray’s time comes from numbagg’s parallel JIT kernels; with bottleneck alone it takes 10 s.

  • Elementwise operations (K → °C, a * 2 + a, astype) are bound by memory bandwidth in both libraries.

  • sel. The selection itself is cheap in both libraries; annoray carries about 2 ms of fixed overhead.

Notes#

  • Threads. annoray parallelises with rayon; set RAYON_NUM_THREADS to limit it. For example, the rolling mean takes 1.25 s on one thread and 0.27 s on 16.

  • Streaming budget. The memory budget for streaming lazy data is set with ar.set_stream_bytes (Python) or annoray::set_stream_bytes (Rust).

  • OpenBLAS threads. The benchmark sets OPENBLAS_NUM_THREADS=1. Otherwise OpenBLAS threads, which scipy and NumPy load, spin idle and take cores from both libraries.
